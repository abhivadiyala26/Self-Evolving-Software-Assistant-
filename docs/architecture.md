# AutoSRE architecture

## Request and recovery flow

1. The React application serves ShopSphere and the protected AutoSRE console. It sends account, order, monitoring, and incident requests to the FastAPI API.
2. The API manages authentication and optional database persistence. Public service health and telemetry are generated by the in-process ShopSphere service simulator.
3. A background monitor in the FastAPI process samples service health and metrics without requiring an open browser. Sustained violations create alerts and incidents.
4. The analysis, RCA, and remediation agents classify the evidence and propose an action. These are implemented as local rule-based modules, not remote AI services.
5. Recovery policy evaluates action bounds, impact, and retries. Bounded actions may run automatically; higher-risk actions wait for an authenticated admin decision.
6. The simulator applies the selected recovery to its modeled service state. The verifier samples affected services and resolves the incident only after recovery is observed.

## Real and simulated components

The FastAPI process, background tasks, authentication checks, incident workflow, risk policy, and SQLAlchemy database integration are application code. SQLite is used locally by default; a configured SQLAlchemy-compatible database such as PostgreSQL can persist accounts, sessions, and orders. In database-free Render demo mode, public demo accounts can sign in, but new accounts and operational state are temporary and orders are unavailable.

ShopSphere microservices, their health/metrics, and recovery execution are simulated in-process. Recovery does not call Kubernetes, cloud APIs, real payment systems, or external monitoring platforms. The frontend charts and console present telemetry returned by this backend simulator.

## Deployment topology

Vercel serves the Vite frontend from `dashboard/`. Render runs the FastAPI backend from the repository root using the compatibility `main.py` entry point and root `requirements.txt`; both forward to the code and dependencies under `backend/`. The frontend's `VITE_API_BASE_URL` points to Render, and Render's `AUTOSRE_CORS_ORIGINS` must allow the Vercel origin.
